# 구조와 변경 원칙

이 사이트는 콘텐츠 데이터와 정적 HTML 생성, 브라우저 동작을 분리한 작은 SSG다. 런타임 서버나 외부 스크립트가 필요하지 않다.

## 데이터가 페이지로 만들어지는 흐름

1. `site/data/`에서 공개 프로필을 관리하고 `content/posts/`에서 공개용 글을 읽는다.
2. `site/pages/`가 콘텐츠를 공통 `escapeHTML`로 이스케이프해 페이지 본문으로 만든다.
3. `site/render.mjs`가 각 경로를 `site/layout.mjs`의 문서와 조합한다.
4. `scripts/build-site.mjs`가 페이지·자산·참조 경로를 검사하고 출력 디렉터리를 교체한다.
5. 브라우저는 공통 CSS 하나와 ES module을 읽는다. 기본 콘텐츠는 JavaScript 없이도 표시된다.

`site/`는 빌드 전용이다. `src/scripts/`는 브라우저 전용이다. 렌더러에서 DOM에 접근하거나 브라우저 코드에서 Node 파일 API를 사용하지 않는다.

## 바꿀 곳

| 변경 | 관리 위치 |
| --- | --- |
| 프로젝트·경력·활동·수상 | `site/data/` |
| 공개용 글 | `content/posts/` |
| 페이지 구획과 콘텐츠 배치 | `site/pages/` |
| 헤더·푸터·검색 메타데이터 | `site/layout.mjs` |
| 배경·글꼴·공통 컨트롤 | `src/styles/base.css` |
| 페이지별 레이아웃 | `src/styles/{home,projects,blog,cv}.css` |
| 프로젝트 선택 상태 | `src/scripts/projects.js` |
| 블로그 분류·검색 이력 | `src/scripts/blog.js` |
| 서버의 블로그 분류 목록 | `site/data/blog.mjs`의 `blogCategories` |

블로그 브라우저 코드는 서버가 렌더링한 분류 버튼을 읽는다. 별도 분류 목록을 다시 선언하지 않는다. 본문은 문자열 문단으로 등록하며 HTML 문자열을 직접 삽입하지 않는다.

경력(`careers`)·활동(`activities`)·수상(`awards`)은 별도 목록이다. 근무 경력으로 확인되지 않은 교내 활동을 경력으로 표시하지 않고, 빈 경력 구획은 생략한다.

## 로컬 글쓰기와 실험안

글쓰기 서버는 127.0.0.1:4320에서만 실행한다. 편집 UI와 초안 저장 경로는 정적 사이트 출력에 포함하지 않는다. 초안 저장, 공개용 등록, 실제 사이트 배포를 구분한다. 공개 등록을 취소해도 기존 운영 배포가 자동 변경되지는 않는다.

`experiments/night/`, `terminal/`, `hangar/`는 밤하늘·ASCII 터미널·WebGL 787을 구현한 독립 시안이다. `catalog.mjs`가 공통 슬로건과 고정할 프로젝트 ID를 관리하고 실제 프로젝트 데이터는 `site/data/projects.mjs`를 그대로 읽는다. 고정 프로젝트는 서로 다른 ID 최대 두 개만 허용한다. 전체 목록은 원본 데이터 전체를 순회하므로 새 프로젝트가 생겨도 별도의 큰 카드를 추가할 필요가 없다.

`experiments/aircraft/model.mjs`는 두 비행기 렌더러가 공유하는 지오메트리다. Node 전용 API 없이 정점·법선·색·윤곽선을 생성한다. 터미널은 이를 텍스트로 투영하고, 3D 안은 WebGL로 렌더링한다. WebGL을 사용할 수 없으면 같은 좌표를 Canvas 선으로 그린다. 그래픽은 조작·크기 변경 때만 다시 그리며 자동 회전 루프나 외부 3D 라이브러리가 없다.

전용 빌드가 `concept-dist/`에 `/`, `/terminal/`, `/hangar/`와 이전 시안 `/indigo/`, `/flight/`, `/archive/`를 생성한다. 127.0.0.1:4321에서 비교하며 필요한 공유 모델과 보관용 그림만 명시적으로 복사한다. 미리보기는 `.mjs`를 JavaScript MIME으로 제공한다. 공개 빌드의 입력은 계속 `src/`이므로 실험안과 비교 컨트롤은 운영 배포에 포함되지 않는다.

주 비교 화면은 별자리와 ASCII 두 안이다. 오리자리는 독립된 정규화 좌표·연결 데이터로 Canvas에 그린다. 프로젝트 이미지는 공통 데이터에서 수집·중복 제거하며 안전한 `/assets/` 이미지 경로와 실제 일반 파일인지 검사한다. 등록한 경력과 최근 공개 글도 공통 데이터에서 읽어, 새 콘텐츠가 생기면 빌드에 반영한다.

후속 절충안 `/horizon/`, `/daybreak/`는 독립 폴더에서 생성한다. 이 안들은 `aircraft-v2/model.mjs`와 `sky-engine/viewer.mjs`를 사용한다. `createSkyViewer(host, options)`가 문자·입체 렌더링과 입력, 짧은 시점 전환을 관리하고, 페이지는 콘텐츠와 조작 버튼을 관리한다. 이전 `aircraft/model.mjs`와 그래픽 동작은 그대로 보존한다. 공용 모듈은 빌더의 명시적 목록으로만 복사하며 공개 빌드와는 분리한다.

추가 하늘 시안 `/atmosphere/`, `/descent/`, `/orbit/`와 `/flight-lab/`도 독립 폴더에서 같은 v2 모형과 렌더러를 사용한다. `setInputOptions`는 입력 조합을, `setOrientation`은 외부 스크롤 장면의 기준 방향을 제어한다. `preserveInput`은 장면의 기준 방향이 바뀌어도 사용자의 드래그 편차를 유지한다. 각 페이지가 생명주기와 버튼을 소유하고, 엔진이 포인터·스크롤·렌더 자원을 정리한다.

후속 비교안 `/constellation/`과 `/sky-trail/`은 첫 화면의 밤하늘과 스크롤 중 787 시점 변화를 먼저 보여주고, 비행기와 분리된 다음 구간에 실제 기록의 별을 놓는다. `/sky-trail/`은 프로젝트·활동별 필수 연결선 뒤에 검토한 공개 커밋 유성을 배치한다. `/constellation-lab/`은 프로젝트 기능·활동 범위와 선택형 레이더 표현을 비교한다. 항공기 조작 버튼은 이 세 화면에 두지 않고, 비행 입력 설정은 기존 `/flight-lab/`에서 계속 비교한다. 별과 라벨은 각 시안의 독립 화면 코드가 배치하고 공통 콘텐츠는 `site/data/`에서 읽는다.

모든 시안의 선택 메뉴는 `experiments/navigation.mjs`에서 생성하며 공용 CSS·JS를 빌더가 연결한다. 빌드 전에 메뉴의 각 경로와 실제 산출물 경로가 일치하는지 확인한다. 별자리와 ASCII도 같은 목록에 포함한다. 메인 페이지의 글 목록은 제거하고 Blog 링크로 이동한다. `commit-records.mjs`는 검토한 공개 저장소 커밋의 고정 스냅샷이며 브라우저에서 API를 호출하거나 비공개 Git 정보를 읽지 않는다.

## 레이아웃

페이지 종류는 HTML의 `data-page`에 표시한다. `--canvas`와 `--ink`를 문서 루트에서 설정하고 body가 같은 값을 사용하므로 스크롤 경계에서도 배경이 이어진다. 짧은 페이지도 최소 화면 높이를 채운다. 내용 구획은 고정 높이로 잘라내지 않는다.

## 실행과 배포

미리보기는 127.0.0.1에만 바인딩하며 생성된 디렉터리만 제공한다. 소스·디렉터리 목록·심볼릭 링크는 제공하지 않는다. 없는 경로는 실제404 응답과 공통 오류 페이지로 표시한다.

공개 빌드는 경로별 canonical·sitemap·robots와 보안 헤더를 만든다. manifest와 ZIP은 `.runtime/deploy/`에 생성한다. 파일별 SHA256을 검사한 ZIP만 기존 Cloudflare Pages 프로젝트에 업로드한다. 운영 상태나 개인 정보가 담긴 로컬 기록은 공개 저장소에 넣지 않는다.
