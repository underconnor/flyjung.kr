# Figma 구현 기준
기준 파일: https://www.figma.com/design/I85IQjtzjZWsy8MVIMhdib?node-id=315-2
페이지: v1 UI. 사용자 요청에 따라 기존 CSS 장식 패널을 제거하고 실제 Figma 화면 및 이미지로 교체했습니다.

## 적용한 화면
- Home Desktop `370:719`, Mobile `370:836` (최신 201 기반 홈)
- Projects 1안 기본 `325:182`, 신성인 `325:214`, 모무 `325:262`
- Projects Mobile `328:1492`, `328:1524`, `328:1571`
- Blog 1안 `327:224`, Empty `327:324`, Mobile `328:1618`
- CV 1안 `327:272`, Mobile `328:1666`

같은 캔버스의 2안 및 ‘기준 원본’ 홈은 비교 시안입니다. 최신 홈의 텍스트 내비게이션과 연결되는 1안으로 일관되게 구현했습니다. 모바일도 Projects/Blog/CV 링크를 그대로 표시합니다.

## 구현
Figma의 React/Tailwind 참고 코드는 기존 Node 정적 빌드에 맞춰 HTML·CSS·ES module로 옮겼습니다. 디자인과 상관없는 프레임워크 의존성은 추가하지 않았습니다. 공통 데이터, 공통 레이아웃, 페이지 템플릿, 브라우저 동작, 스타일을 분리했습니다.

페이지 배경은 Home #f7f6f2, 하위 페이지 #fcfcfa입니다. 하위 페이지 본문 폭1120px, Home1248px, 모바일 여백24px를 적용했습니다. 좁은 화면320px도 지원하며, 중간 화면에서는 자연스럽게 축소·재배치합니다.

## 실제 자산
Figma get_design_context가 반환한 PNG4개를 내려받아 `src/assets/projects/`에 저장했습니다. 신성인 급식·한줄평, 모무 미션·피드 이미지를 지정 슬롯에 배치하며 임시 Figma URL을 런타임에 사용하지 않습니다. 원본 전체 화면 렌더를 페이지 배경으로 사용하지 않았습니다.

Noto Sans KR 가변400–700을 Google Fonts 공식 v40 WOFF2로 자체 호스팅합니다.
- https://fonts.google.com/noto/specimen/Noto+Sans+KR
- https://github.com/google/fonts/tree/main/ofl/notosanskr
Unicode 범위별 파일은 필요한 문자만 다운로드하며, OFL은 `src/assets/fonts/noto-OFL.txt`에 보존합니다.

## 공개 콘텐츠
현재 Figma에서 확인한 프로젝트·CV 정보를 사용합니다. Figma의 ‘예시 콘텐츠’ 블로그 행은 실제 게시글로 발행하지 않았으며, 빈 상태가 현재 운영 데이터입니다. 실제 글을 등록하면 검색·필터·목록과 상세 페이지가 함께 활성화됩니다. 기존 비공개 원본 PDF·검토/연구 문서는 모든 빌드에서 제외합니다.

## 확인 근거
Figma 컨텍스트는 `.runtime/figma/`, 실제 Chrome 데스크톱·모바일 스크린샷은 `output/playwright/figma/`에 로컬로 보존합니다. 원래 코드는 `.runtime/backups/before-figma-refactor.tar.gz`에 보관했습니다.

## 별도 비교 시안 — 2026-10-23

사용자의 후속 요청에 따라 기존 안은 유지하고 `experiments/bold/`에 과감한 비교 시안을 따로 만들었습니다. 본안의 수정은 활동·수상 구분과 블로그 빈 상태 문구에 한정합니다. 확인된 근무 이력이 없어 경력은 별도 데이터 목록으로만 준비하고 빈 구획은 표시하지 않습니다.

비교 시안은 코발트색 첫 화면, 큰 영문 타이포, 실제 신성인·모무 화면을 중심으로 구성합니다. 세 가지 영어 슬로건은 확정 전 가안이며 화면에서 직접 바꿔 볼 수 있습니다. 화면 폭이 좁아지면 프로젝트 본문과 이미지, 활동 목록이 세로로 재배치됩니다. 자세한 색상·구성 기준은 `experiments/bold/README.md`에 기록합니다.

이 시안은 전용 `concept-dist/`에만 빌드하고 로컬 4321 포트에서 비교합니다. 글쓰기 화면은 별도 로컬 4320 포트에서 실행합니다. 둘 다 기존 공개 빌드와 배포 ZIP에서 제외하며, 이번 비교 작업으로 운영 사이트를 변경하지 않습니다.

## 인디고와 비행기·오리 — 2026-10-23

사용자가 개성은 좋지만 기존 색과 영문 슬로건은 마음에 들지 않는다고 했고, 인디고 계열을 선호한다고 밝혔다. 이 피드백에 따라 두 안을 병렬로 제작했다.

| 안 | 핵심 | 로컬 경로 |
| --- | --- | --- |
| 인디고 타이포 | 흰 바탕, 딥 인디고 `#42396c`의 큰 이름, 연라벤더 앱 화면 | `/` |
| 비행기와 오리 | 같은 인디고 계열에 직접 생성한 오리·종이비행기 그림과 작은 노랑 포인트 | `/flight/` |
| 이전 파랑안 | 기존 구성과 슬로건 비교를 보존 | `/archive/` |

큰 영어 선언문 대신 이름을 중심에 두었다. 비행기 안의 `Grounded, mostly.`는 작은 서명 가안이며 확정된 슬로건이 아니다. 비행·여행 경력은 새로 만들지 않았다. ‘한 바퀴 날기’는 사용자 조작에만 반응하고 시스템의 움직임 줄이기 설정을 따른다.

각 안의 색·구성·검토 기록은 `experiments/studio/README.md`, `experiments/flight/README.md`에 있다. 이미지 자산과 생성 프롬프트는 비행기 시안 폴더에 함께 보관한다. 기존 공개 사이트와 글쓰기 기능에는 변경이 없다.

## 밤하늘·터미널·787 3D — 2026-10-24

후속 피드백에서 사용자는 밝은 인디고 대신 밤하늘처럼 매우 어두운 인디고 블루, 별, 큰 영어 슬로건을 요청했다. 비행기 취향은 Boeing 787이며 개성은 이미지 합성이 아닌 터미널 그래픽이나 직접 조작하는 3D로 표현한다.

확정 슬로건은 **Somewhere between code and stars.**다. 공통 배경 `#080c24`, 흰 타이포, 밝은 인디고 별빛을 사용한다. 이전 코발트 안의 큰 타이포 비중을 살리고 세 방향을 병렬로 구현했다.

| 안 | 표현 | 조작 |
| --- | --- | --- |
| 밤하늘 `/` | 큰 슬로건 옆에 코드로 그린 별 | 포인터·키보드 반응, 별자리 연결, 섹션 이동 |
| 터미널 `/terminal/` | 공유 787 모델을 ASCII로 투영 | 도움말·작업 조회·시점·회전 명령, 입력 이력 |
| 787 3D `/hangar/` | 깊이와 조명이 있는 WebGL 모델 | 드래그·방향키·시점 프리셋·확대·윤곽선 |

세 안 모두 CV를 프로젝트보다 먼저 배치한다. 실제 프로젝트 두 개를 고정 표시하고, 이후 프로젝트는 전체 목록에서 관리한다. 밝은 안과 그림 안은 각각 `/indigo/`, `/flight/`로 옮겨 보존했다. 세부 기준과 787 참고 자료는 각 실험 폴더의 README에 기록한다. 모든 작업은 로컬 비교용이며 운영 배포는 유지한다.

같은 작업 중 받은 후속 피드백으로 별자리 안을 주안으로 정하고 바탕을 `#090f35`로 조정했다. 별자리 연결은 처음부터 켜고, 작은 버튼으로 29개 별이 그리는 오리자리를 찾아볼 수 있게 했다. 비행기와 오리는 합치지 않는다. ASCII 안은 사각 터미널 틀을 제거하고 짙은 파란 하늘에 문자 비행기를 배치했으며 명령 입력은 접는 조작부로 줄였다. 독립 3D 모델 안은 보관하고 주 비교 메뉴에서 제외했다.

## 이름과 읽는 면을 중심으로 한 절충안 — 2026-10-24

사용자는 별자리 안의 색과 ASCII 787을 선호하지만, 본문까지 어두운 구성·이름보다 큰 슬로건·뜻 없는 별과 점선·오리자리를 다시 지적했다. 기존 시안은 그대로 보존하고 `/horizon/`, `/daybreak/` 두 경로를 추가한다.

- A는 깊은 파랑 상단에서 밝은 회청색 본문으로 이어진다. 이름을 주 제목으로 두고, 별을 실제 프로젝트와 활동의 연도에 연결한다. 같은 연도 항목 사이에 확인되지 않은 선후 관계를 만들지 않는다.
- B는 밝은 미색 지면에 이름과 이력을 펼치고, 인디고 장면에 실제 ‘만든 것’과 ‘참여한 곳’을 나눠 연결한다. 별이 장식 이상의 탐색 역할을 갖게 한다.
- 슬로건은 보조 문장으로 낮춘다. CV→고정 두 프로젝트→검색 가능한 전체 목록→기록 순서는 유지한다. 별과 항공기는 서로 다른 개인 취향·이력 요소로 설명하며 오리자리와 장식 점선은 새 안에 사용하지 않는다.
- 787은 새 지오메트리와 공유 렌더러로 분리한다. 이전 모델을 바꾸지 않고 기수·날개·엔진 비율을 손본다. 문자와 입체는 같은 카메라를 공유하고, 입력에 반응하는 짧은 모션만 사용한다. 반복 자동 회전은 없다.

두 안의 차이는 단순한 배경색 교체가 아니라 밤하늘과 읽는 지면의 비중·배치다. 과도한 기념물 같은 슬로건이나 장식용 계기판을 추가하지 않고, 실제 이름·콘텐츠·선택 가능한 그래픽에 집중한다.

## 열린 하늘과 하강하는 페이지 — 2026-10-24

사용자는 별자리와 ASCII를 계속 동등한 시안으로 비교하고 싶어 한다. 전체 시안 선택기를 모든 경로에 제공하고, 메인의 Notes 영역은 제거하며 Blog 메뉴로 직접 연결한다. Daybreak의 내부 사각 하늘 패널은 없애고 페이지 자체가 새벽 하늘이 되도록 바꾼다. Horizon은 실제 프로젝트·활동을 문자 별로 흩어 놓고, 참여 관계를 선택했을 때 강조한다.

세 추가 안은 같은 하늘을 다른 속도로 읽게 한다. Atmosphere는 심야 인디고에서 푸른 대기와 밝은 CV로 끊김 없이 이어지는 그라데이션, Descent는 스크롤에 따라 787과 실제 커밋 별을 지나 내려가는 구성, Orbit는 짧은 도입부의 열린 하늘과 얕은 밝기 전환에 집중한다. 큰 그래픽 박스와 장식 점선은 사용하지 않는다. 이름은 가장 크고, 슬로건은 보조 문장이다. 별의 정보는 실제 프로젝트·활동·이 저장소의 커밋에만 연결한다.

별도 비행 실험실은 드래그·스크롤·포인터 입력, 축, orbit/bank 방식, 감도·관성을 비교하게 한다. 기존 공유 렌더러의 기본 동작은 유지하고 설정 API를 추가한다. 기본은 시스템 모션 감소 설정을 따르며, 네이티브 스크롤을 가로채지 않는다. 입력·장면이 멈추면 렌더도 멈춘다. 개별 시안의 색·타이포·배치 계획은 각 README에 기록한다.

## 점 별자리와 787의 밤하늘 — 2026-10-26

사용자는 Atmosphere의 이름·기체 배치를 선호하고 Descent의 큰 787과 스크롤 반응을 원했다. 새 `/constellation/`은 첫 화면을 균일한 밤하늘로 두고, 스크롤 이후에만 밝은 본문으로 전환한다. 두 고정 프로젝트는 `만든 것`, PRON→AI대학 학생회→IT지원위원회는 실제 활동 시작 순으로 연결한다. 각 별의 짧은 설명선은 관측도의 표기 방식처럼 이름과 역할을 가리킨다. 무작위 별은 배경 질감만 담당한다.

`/constellation-lab/`은 실제 프로젝트 기능·활동의 범위를 바꾸며 별 모양을 비교하고, 레이더는 선택형 실험으로 둔다. `/sky-trail/`은 별도의 검은 하늘에 실제 기록의 별자리 군집을 놓는 안이다. 세 안 모두 비행기 조작 버튼과 안내 문구를 화면에 두지 않는다. 787은 공유 모델을 사용하며 항공 업무 경력으로 암시하지 않는다. 기존 12개 시안과 운영 본안은 보존한다. 새 방향은 아직 최종 선택이나 운영 배포가 아니다.

같은 날의 추가 피드백에서 사용자는 단순한 직선·삼각형이 별자리처럼 보이지 않고, 별자리와 787이 함께 내려가는 구성도 원하지 않는다고 명확히 했다. 따라서 새 시안은 **비행기만 있는 첫 밤하늘 → 비행기와 분리된 별자리 관측 구간 → 밝은 CV 본문**의 순서로 다시 구성한다. 별의 항로에는 다섯 기록의 이름과 같은 범주의 필수 연결만 남기고, 레이더 원·눈금은 실험실의 선택형 안에서만 비교한다. 별의 항로는 관측 구간을 더 위쪽의 검은 하늘에 놓고, 밝아지는 구간에 검증된 공개 커밋을 별똥별처럼 표시한다. 787은 첫 장면의 위쪽에 두고 스크롤 자세 변화를 더 또렷하게 한다.
