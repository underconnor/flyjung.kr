# 순항 — 별의 항로와 별도로 비교하는 안

`/cruise/`는 2026-10-28의 시각 피드백을 검토하기 위한 로컬 실험안이다. 기존 `/sky-trail/`과 운영 사이트의 소스는 보존한다. 최종 디자인이나 운영 배포로 선택된 상태가 아니다.

## 화면의 순서

1. 단색에 가까운 심야 하늘에 **정지원 / Jiwon Jung**을 가장 큰 글자로 둔다. `Somewhere between code and stars.`는 보조 문장이다. 오른쪽에는 화면 조작 버튼이 없는 ASCII Boeing 787을 둔다.
2. 왼쪽 하늘에 짧은 별 무리 두 개를 둔다. 프로젝트는 신성인과 모무, 활동은 PRON·AI대학 학생회·IT지원위원회다. 군집이 끝나는 지점에서 선도 끝난다. 비행기와 별을 잇지 않는다.
3. 밝아지는 하늘에는 검토된 공개 커밋 두 개를 짧게 지난다. 이 부분이 별도 세로 목록처럼 보이지 않도록 제목과 반복 구분선을 화면에 추가하지 않는다.
4. 밝은 본문은 **CV → 고정 프로젝트 최대 두 개 → 검색 가능한 전체 프로젝트** 순서다. CV의 첫 문장은 실제로 만든 앱과 맡은 활동을 1인칭으로 적고, 활동의 역할·기간은 가는 구분선 없이 여백으로 묶는다. 두 프로젝트는 동일한 카드 두 장이 아니라 서로 다른 위치의 실제 화면 이미지로 보여 준다. 전체 목록은 작게 접힌 상세 인덱스로 남긴다. Blog는 별도 페이지로 간다.

데스크톱에서 두 별 무리는 왼쪽 공간을 가로로 나누어 쓰고, 모바일에서는 짧은 두 무리를 위아래로 놓는다. 화면이 좁다고 두 경로를 한 화면 높이의 평행선으로 늘리지 않는다.

## 표현 규칙

- 밤하늘 `#080d2c`, 선명한 항성 `#f8fbff`, 멀리 있는 별 `#a9c6e8`, 대기 `#344f78`, 밝은 바탕 `#eef3f8`, 본문 잉크 `#182c49`를 기본 팔레트로 한다. 기존 Noto Sans KR을 사용하고 글자 비행기에만 고정폭 문자를 쓴다.
- 별은 외곽 UI 고리 없이 작은 선명한 점과 약한 빛 번짐으로 그린다. 광도와 크기가 서로 다르지만 임의의 별에 실제 경력 의미를 붙이지 않는다. [NASA Tycho Skymap](https://svs.gsfc.nasa.gov/3572)의 광도 차이와 [IAU 별자리 설명](https://www.iau.org/IAU/IAU/Astronomy-FAQs/Constellations.aspx)의 관측도 선 표현을 시각 참고로만 쓴다. 실제 천체의 위치나 별자리 이름을 재현한다고 주장하지 않는다.
- 연결선은 기본 상태에서 매우 흐리게 두고, 별에 hover 또는 키보드 포커스를 두면 해당 무리만 밝힌다. 작은 경유 별에는 이름·날짜·링크가 없고 보조 기술에서 숨긴다. 선은 기록을 읽는 순서이지 조직 승계나 프로젝트의 인과관계가 아니다. 신성인·PRON의 기간은 겹치므로 서로 잇지 않는다.
- 787은 현재 시안의 큰 하강·시점 회전·기울임을 그대로 옮기지 않는다. 화면에서 약간 대각으로 이동하며 거의 같은 3/4 자세를 유지한다. 지나가는 별과 밝아지는 대기가 전진감을 보조한다. [FAA Airplane Flying Handbook의 안정된 접근 설명](https://www.faa.gov/sites/faa.gov/files/regulations_policies/handbooks_manuals/aviation/airplane_handbook/17_afh_ch16.pdf)은 큰 자세 급변을 피하는 시각 원칙이고, 실제 활공각을 픽셀에 매핑하지 않는다. 787의 형상은 [Boeing 3면도](https://www.boeing.com/commercial/airports/3-view)와 기존 공유 모델을 기준으로 한다.
- 좁은 화면에서는 787의 날개와 꼬리를 읽기 쉽도록 조금 위에서 보는 3/4 시점을 쓴다. 320px의 방위·고도 `.25/1.0`에서 768px 이상의 `.52/.62`까지 연속 보간한다. 공유 모델과 다른 시안의 시점은 바꾸지 않는다.
- 유성은 검토된 실제 커밋 `ff7cfa2`의 블로그 터치·글 이동과 `367696f`의 로컬 글쓰기 화면을 가리킨다. 보이는 한국어 문장은 각 커밋의 작업을 짧게 옮긴 것이며 링크·날짜·SHA는 원본을 유지한다. 접근 가능한 링크 이름에 원문 제목도 남긴다.
- 근무 경력은 확인된 데이터가 없으므로 만들지 않는다. PM은 숭실대학교 IT지원위원회에만 붙인다. SSU Bug Bounty 장려상에는 확인되지 않은 수상 날짜를 쓰지 않는다.

## 구현 경계와 확인할 것

`render.mjs`는 검토된 `site/data/`와 고정 프로젝트 목록을 읽어 문서를 만든다. `concept.css`는 이 안의 배치와 별·이미지 질감을 담당한다. `concept.js`는 두 군집의 실제 점 중심을 잇는 SVG 선, 링크·검색·해시, 787의 스크롤 자세, 움직임 줄이기, 공개 커밋의 한 번만 실행되는 모션을 담당한다. 공유 `sky-engine`과 787 모델은 수정하지 않는다.

실제 브라우저에서 첫 화면, 두 별 무리, 하늘에서 CV로 넘어가는 장면, 프로젝트 이미지와 검색을 320·390·530·768·1440px 이상에서 확인한다. 별과 기체/라벨의 겹침, 가로 넘침, 링크 목적지·키보드 포커스, 검색 URL과 직접 해시, 움직임 줄이기, 콘솔/실패 자산 요청을 확인한다. 정지 캡처만으로 비행 모션이나 물리 모바일 터치를 검증했다고 기록하지 않는다.
